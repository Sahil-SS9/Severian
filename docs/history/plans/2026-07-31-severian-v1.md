# Severian v1 Implementation Plan

> **Execution:** Direct chat execution with specialist coding and independent QA delegation. Strict RED→GREEN TDD for production behaviour.

**Goal:** Ship a complete standalone, local-first memory platform that preserves original source content and all derived memories, exposes API/CLI/MCP/Hermes/admin interfaces, and can add isolated customer deployments soon after local validation.

**Architecture:** A Python service owns canonical observations, memories, provenance, revisions, entities, relations, jobs, audit events and access scopes. SQLite is the Phase 1 canonical store; lexical and vector indexes are rebuildable derived projections behind explicit interfaces. PostgreSQL implements the same repository contract for scalable isolated customer deployments. A React web application consumes the HTTP API; MCP and Hermes are adapters, never authorities.

**Stack:** Python 3.12, uv, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, SQLite/FTS5, PostgreSQL/pgvector adapter, Typer, pytest, mypy/ruff; React, TypeScript, Vite, Vitest/Testing Library, Playwright.

## Locked decisions

1. Repository: `/home/kensei/repos/Severian`.
2. Phase 1: local-first, single-node and single-tenant.
3. Phase 2 follows soon after Phase 1 validation.
4. Original sources and every derived memory are retained separately.
5. Every derivation records source IDs, model identity, prompt version, confidence and timestamp.
6. Local models are default; approved cloud models are optional and collection policy can forbid them.
7. v1 ships backend, HTTP API, Python SDK, CLI, MCP, Hermes adapter and web admin.
8. SQLite is Phase 1 canonical storage; separate indexes are rebuildable.
9. Phase 2 starts with isolated customer data planes, not shared-table tenancy.
10. PostgreSQL conformance is required before high-concurrency customer activation.
11. Supermemory is an external provider only.

## Invariants

- One canonical write path.
- Tenant, profile, collection, agent and session scopes are explicit on every record.
- Original evidence is immutable; corrections create revisions or supersession links.
- Deletion is auditable, deterministic and propagated to derived indexes.
- Derived indexes can be deleted and rebuilt without losing canonical data.
- No cloud call when policy forbids it.
- No cross-scope recall.
- Stable application UUIDs; no database-specific identity leaks.
- Export and restore do not depend on the original machine.

## Phase 0 — Foundation

Deliverables:
- repository, licence decision placeholder, pyproject, web workspace, CI-quality commands;
- architecture and threat-model documents;
- typed domain contracts and repository/index ports;
- migration and configuration structure.

Exit criteria:
- clean install in a new uv environment;
- quality commands execute;
- first contract tests fail before implementation and pass afterwards;
- no dependency on KenseiAgent or Mnemosyne.

## Phase 1 — Canonical SQLite storage

Deliverables:
- scoped observations with content hash and source metadata;
- memories with type, provenance, confidence and model/prompt lineage;
- entities, temporal relations, revisions and supersession;
- collections and local policy;
- durable jobs/outbox and audit events;
- SQLite WAL repository and migrations;
- backup, restore and export/import primitives.

Validation:
- idempotent duplicate ingestion;
- correction preserves original evidence;
- scope isolation;
- crash-safe transactions;
- SQLite integrity and clean-machine restore;
- contract tests reusable against PostgreSQL.

## Phase 2 — Memory engine and indexes

Deliverables:
- ingestion pipeline and normalisation;
- pluggable local/cloud derivation gateway;
- extraction and reconciliation;
- FTS5 lexical projection;
- pluggable local vector projection;
- hybrid retrieval, ranking and token-budgeted context assembly;
- index lag tracking, repair and complete rebuild.

Validation:
- local-only operation;
- cloud-deny policy fails closed;
- source citations on every result;
- temporal corrections and deletion propagation;
- deterministic index rebuild from canonical data.

## Phase 3 — Product interfaces

Deliverables:
- versioned FastAPI surface and OpenAPI;
- Python SDK;
- Typer CLI;
- MCP tools;
- Hermes MemoryProvider adapter;
- health, readiness and metrics endpoints.

Validation:
- interface contract tests;
- idempotency and auth checks;
- malformed request and unavailable-index behaviour;
- no adapter bypasses application services.

## Phase 4 — Web administration

Deliverables:
- source and memory browser;
- provenance/revision timeline;
- search and context preview;
- correction, invalidate and deletion flows;
- export, import, backup and restore controls;
- job, index and service health views;
- local authentication.

Validation:
- component tests;
- accessibility checks;
- Playwright browser journeys;
- destructive actions require explicit confirmation and produce audit events.

## Phase 5 — PostgreSQL and isolated customer deployment

Deliverables:
- PostgreSQL repository and pgvector option;
- same conformance suite as SQLite;
- customer data-plane deployment package;
- independent DB/index/volume/keys/backups per customer;
- optional shared control-plane contract, without customer memory content.

Validation:
- identical observable repository behaviour;
- concurrent writers and workers;
- migration SQLite→PostgreSQL→export;
- zero cross-customer access in adversarial tests;
- backup/restore and key separation.

## Phase 6 — Migration and release

Deliverables:
- Mnemosyne importer as a migration adapter, not a runtime dependency;
- dry-run report, shadow recall comparison and reversible cutover;
- release package, Docker deployment, runbook and operator guide.

Release gates:
- all unit, contract, integration and E2E suites pass;
- ruff, mypy, TypeScript and dependency/security checks pass;
- no high/critical security finding;
- two clean backup/restore rehearsals;
- two migration/rollback rehearsals;
- held-out retrieval benchmark meets approved baseline;
- independent Quan QA and Kensei Review pass;
- no claim of production cutover until separately authorised.
